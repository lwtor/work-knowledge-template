# AI 知识库使用规则

## 1. 知识库定位

本库是个人工作记忆库，包含两类主要内容：

- `Knowledge/`：跨项目可复用的技术经验、技巧和问题解决方法。
- `Projects/`：某个需求或项目的过程资料、链接、想法、待办和结论。

Markdown 文件是本库内部的事实来源。公司正式需求系统、代码仓库、合同系统和审批系统仍是正式业务事实来源。

## 1.1 新 Agent 接入

新的 AI Agent 接入本库时，先读取 `AI/启动配置.md`，再读取本文件。Agent 必须检查实际的读取、搜索和写入能力，并向用户报告结果。不能因为读到了规则文件，就假设自己拥有本地写入权限。

如果存在 `AI/LOCAL.md`，在本文件之后读取它。`AI/LOCAL.md` 是用户个人补充规则，模板更新时不得覆盖。

## 2. 检索规则

回答与历史工作有关的问题前：

1. 搜索用户问题中的关键词、项目名、系统名、错误信息和可能的别名。
2. 阅读相关文件正文，不能只根据文件名回答。
3. 优先使用标记为 `confirmed`、状态为 `active` 的内容。
4. 明确区分知识库事实、AI 推断和仍需确认的信息。
5. 回答中列出引用的文件路径；若有 URL，也一并列出。

如果没有找到可靠记录，应明确说“知识库中没有找到相关记录”，不能假装已经记录过。

## 3. 整理对话规则

用户说“整理到知识库”“记住这次解决方法”或类似表达时：

1. 提取问题、背景、关键结论、步骤、适用条件和来源。
2. 判断属于 `Knowledge/`、`Projects/` 还是暂存到 `Inbox/`。
3. 搜索已有内容，检查是否应该更新旧笔记而不是新建重复笔记。
4. 不补造用户没有提供的时间、人员、原因、链接或结论。
5. 缺失或未经验证的内容标记为 `unverified`。
6. 正式写入前先展示拟新增或修改的文件和摘要，等待用户确认。
7. 写入后在 `AI/写入日志.md` 记录变更，并向用户报告结果。

## 4. 项目资料规则

项目相关的需求、设计、测试、开发记录、待办和 URL 放在对应的 `Projects/项目名/` 下。

- 本地文件不复制时，记录相对路径或绝对路径来源。
- URL 至少记录标题、类型、链接和用途说明。
- 项目总览只保存索引和关键结论，详细内容放在独立笔记中。
- 待办事项应使用任务管理工具或项目的 `待办.md`，不要把临时任务散落在知识笔记中。

## 5. 写入安全规则

- 不得静默覆盖已有文件或删除资料。
- 不得自动合并有冲突的结论。
- 删除、合并、归档和大范围改名必须单独获得用户确认。
- 密码、密钥、Token 和不必要的个人隐私不得写入本库。
- `restricted` 内容不得交给远程 Agent 或外部服务。
- 发现敏感信息时暂停写入并提醒用户。

## 6. 输出格式

回答历史知识问题时，建议包含：结论、已确认事实、推断或待确认项、参考文件。

完成写入后，报告：新增文件、更新文件、建立的关联、未写入内容和待确认事项。
