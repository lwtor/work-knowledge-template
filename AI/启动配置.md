# 知识库 Agent 启动配置

这份文件用于让新的 AI Agent 接入本知识库。用户可以把本地目录地址或 GitHub 仓库地址告诉 Agent，Agent 应先完成初始化和接入检查，再执行具体任务。

## 用户给 Agent 的最短指令

```text
我的个人知识库位于：

[知识库根目录]

请先读取其中的 AI/启动配置.md 和 AI/AI-GUIDE.md，
检查你是否具备读取、搜索和写入权限，然后向我报告接入结果。
不要在检查完成前修改任何文件。
```

## 用户只提供 GitHub URL 时

如果用户只提供 GitHub URL，Agent 应：

1. 先确认用户希望保存到哪个本地目录；如果用户没有指定，提出一个明确的建议路径；
2. 检查目标目录是否已存在，存在时不得覆盖；
3. 使用 Git 克隆或其他获准方式下载仓库；
4. 读取仓库的 `README.md`、本文件和 `AI/AI-GUIDE.md`；
5. 报告本地路径、读取权限、搜索权限和写入权限；
6. 未经用户授权，不上传本地资料、不提交 Git、不删除已有目录；
7. 如果无法执行克隆或本地写入，明确说明原因，并给出用户可以手动执行的命令或步骤。

如果存在 `.kb-role`，先读取它：

- `template`：这是可复制的模板仓库，不应写入个人工作资料；
- `personal`：这是包含用户数据的个人知识库，更新时必须保护数据目录。

如果仓库中存在 `scripts/setup.sh`，优先先阅读脚本，再在用户确认的空目录中执行；如果目标目录非空，不得强行执行或覆盖。

如果仓库中存在 `skills/`，根据任务读取对应的 `kb-ingest`、`kb-query` 或 `kb-project` 规范。

## 已有个人知识库的更新

如果用户已经在其他电脑产生了个人数据，不要重新覆盖整个目录。先确认当前目录是个人知识库 Git 仓库，并确保没有未提交修改；然后只更新模板框架文件：

- `README.md`
- `AGENTS.md`
- `Home.md`
- `AI/`（保留 `AI/LOCAL.md`）
- `Templates/`
- `scripts/`
- `skills/`
- `.gitignore`
- `.kb-version`

默认保护、不得由模板更新覆盖的个人数据目录：

- `Knowledge/`
- `Projects/`
- `Daily/`
- `Inbox/`
- `Attachments/`

如果仓库提供 `scripts/update-framework.sh`，优先使用它。更新前必须先提交个人修改或完成备份；更新后运行 `scripts/verify.sh`，并向用户报告框架版本和受保护的数据目录。

用户可使用以下指令：

```text
这是我的知识库 GitHub 地址：

[GitHub URL]

请把它在本地初始化为可用知识库。先检查目标路径和你的读写权限，
不要覆盖已有目录，不要导入其他资料，不要上传本地文件。
完成后报告本地路径、Obsidian 打开方式和仍需要我操作的事项。
```

## Agent 接入流程

### 第一步：确认目录

检查用户提供的路径是否存在，并确认它包含：

- `Home.md`
- `AI/启动配置.md`
- `AI/AI-GUIDE.md`
- `Knowledge/`
- `Projects/`
- `Inbox/`

如果不是本知识库，应停止并提醒用户确认路径。

### 第二步：读取规则

完整读取 `AI/AI-GUIDE.md`，以它作为后续检索、整理和写入规则的依据。

### 第三步：检查能力

Agent 应分别检查：

| 能力 | 检查方式 |
|---|---|
| 读取 | 读取 `Home.md` |
| 搜索 | 搜索 `Knowledge/` 和 `Projects/` 中的关键词 |
| 新建 | 仅在用户授权后，尝试创建临时测试文件或目标文件 |
| 更新 | 仅在用户授权后，修改指定文件 |
| 删除 | 默认不具备，必须单独确认 |
| 远程上传 | 默认禁止 |

不能通过检查的能力不能假设可用。

### 第四步：向用户报告

报告应说明：

- 知识库路径；
- 规则文件是否读取成功；
- 是否可以读取和搜索；
- 是否可以新建和更新文件；
- 是否可以删除文件；
- 是否存在远程上传限制；
- 当前仍需要用户完成的操作。

### 第五步：按权限降级

如果 Agent 只有读取权限：

- 可以检索和总结；
- 不能声称已经保存；
- 可以生成待保存的 Markdown 内容和建议路径；
- 请用户手动复制，或授权写入权限。

如果 Agent 无法访问本地目录：

- 明确说明无法直接读取或保存；
- 可以让用户上传相关文件；
- 可以生成完整 Markdown 内容供用户保存；
- 不得把聊天中的输出描述为已写入知识库。

如果 Agent 可以写入：

- 仍需遵守 `AI/AI-GUIDE.md` 的查重、预览和确认规则；
- 未经确认不得删除、覆盖、合并或大范围移动文件。

## 接入成功后的简短报告示例

```text
知识库接入检查完成。

- 路径：/Users/xxx/Work-Knowledge
- 规则读取：成功
- 本地读取：可用
- 本地搜索：可用
- 新建文件：可用，但正式写入前需要确认
- 更新已有文件：可用，但需要确认
- 删除文件：不可用/需要单独确认
- 远程上传：禁止

现在可以让我检索知识库，或整理内容并在确认后写入。
```
