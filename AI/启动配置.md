# 知识库 Agent 启动配置

这份文件用于让新的 AI Agent 接入本知识库。用户可以把本地目录地址或 GitHub 仓库地址告诉 Agent，Agent 应先完成初始化和接入检查，再执行具体任务。

仅在手动离线复制模板时使用 scripts/setup.sh；GitHub 一键创建或接入必须以 BOOTSTRAP.md 为准，不能调用该脚本。知识库建立后会注册 Codex / BlueCode / vBuddy 全局 work-knowledge skill，后续会话无需重复提供路径。Windows 使用 PowerShell 安装与验证脚本；macOS/Linux 使用 Bash 脚本，不得跨系统借用错误的 Skill 目录。

本文件属于个人仓库。BOOTSTRAP 完成 clone 后，后续逻辑只以本仓库文件为准，不比较模板版本，也不从模板借用脚本。当前版本缺少某项能力时应报告并按现有能力降级，不能把拒绝升级视为不可使用。

接入时必须读取 `.kb-layout-version`：缺失或值为 1 使用旧目录并将仓库根目录作为 Obsidian Vault；值为 2 使用 `Vault/` 内容目录并提示用户在 Obsidian 中打开该子目录。不得根据模板版本猜测私人库布局。

## vBuddy 自接入

当 `.kb-role` 为 `personal` 且当前 Agent 是 vBuddy 时，只按本个人仓库提供的文件完成接入：

1. 如果本仓库包含 `integrations/vbuddy/work-knowledge/` 和当前系统对应的安装脚本，执行本仓库自己的安装脚本。
2. Windows 使用 `scripts/install-vbuddy-skill.ps1`；macOS/Linux 使用 `scripts/install-vbuddy-skill.sh`。
3. 安装后明确验证 vBuddy：Windows 使用 `scripts/verify.ps1 -Agent Vbuddy`；macOS/Linux 使用 `scripts/verify.sh --agent vbuddy`。
4. vBuddy 在每个会话启动时加载全局 Skill；安装或更新 Skill 后提示用户新开一个会话即可生效，无需重启进程。
5. 如果当前旧版本没有这些文件，报告该版本不支持全局 Skill 自动定位，但继续提供当前会话可用的读取、搜索或写入能力。
6. 不得返回模板仓库借用脚本，不得因为缺少新版能力而要求或自动执行框架升级。

## 用户给 Agent 的最短指令

```text
我的个人知识库位于：

[知识库根目录]

请先读取其中的 AI/启动配置.md 和 AI/AI-GUIDE.md，
检查你是否具备读取、搜索和写入权限，然后向我报告接入结果。
不要在检查完成前修改任何文件。
```

## 一句话初始化

用户从公开 BOOTSTRAP.md 发起一键创建或接入时，BOOTSTRAP.md 是唯一权威流程。用户提供的目录是父目录，最终仓库为 父目录/work-knowledge。该流程使用 git clone，禁止调用 scripts/setup.sh，也不得因为父目录非空而拒绝。

scripts/setup.sh 只用于用户已经手工克隆模板后，将模板复制到一个新的最终空目录；它不属于 GitHub 一键创建流程。

## 已有个人知识库的更新

如果用户已经在其他电脑产生了个人数据，不要重新覆盖整个目录。先确认当前目录是个人知识库 Git 仓库，并确保没有未提交修改；然后只更新模板框架文件：

- `README.md`
- `AGENTS.md`
- `Home.md`
- `AI/`（保留 `AI/LOCAL.md`、旧写入日志和月度写入日志）
- `Templates/`
- `scripts/`
- `integrations/codex/`
- `integrations/bluecode/`
- `integrations/vbuddy/`
- `.gitignore`
- `.gitattributes`
- `.kb-version`

默认保护、不得由模板更新覆盖的个人数据包括：布局 1 的全部旧内容目录、整个 `Vault/`、`.kb-layout-version`，以及：
- `AI/LOCAL.md`
- `AI/写入日志.md`
- `AI/写入日志/`

如果仓库提供 `scripts/update-framework.sh`，优先使用它。更新前必须先提交个人修改或完成备份；更新后运行 `scripts/verify.sh`，并向用户报告框架版本和受保护的数据目录。

用户可使用以下指令：

```text
这是我的知识库 GitHub 地址：

[GitHub URL]

请把它在本地初始化为可用知识库。先检查目标路径和你的读写权限，
不要覆盖已有目录，不要导入其他资料，不要上传本地文件。
完成后报告本地路径、Obsidian 打开方式和仍需要我操作的事项。
```

## Agent 接入流程

### 第一步：确认目录

检查用户提供的路径是否存在，并确认它包含：

- `AI/启动配置.md`
- `AI/AI-GUIDE.md`
- `.kb-role`
- 可解析的内容布局：缺少 `.kb-layout-version` 或值为 1 时检查旧内容目录；值为 2 时检查 `Vault/首页.md` 和新版内容目录

如果不是本知识库，应停止并提醒用户确认路径。

### 第二步：读取规则

完整读取 `AI/AI-GUIDE.md`，以它作为后续检索、整理和写入规则的依据。

### 第三步：检查能力

Agent 应分别检查：

| 能力 | 检查方式 |
|---|---|
| 读取 | 按布局读取 `Home.md` 或 `Vault/首页.md` |
| 搜索 | 搜索布局解析后的知识和项目目录 |
| 新建 | 仅在用户授权后，尝试创建临时测试文件或目标文件 |
| 更新 | 仅在用户授权后，修改指定文件 |
| 删除 | 默认不具备，必须单独确认 |
| 远程上传 | 默认禁止 |

不能通过检查的能力不能假设可用。

### 第四步：向用户报告

报告应说明：

- 知识库路径；
- 规则文件是否读取成功；
- 是否可以读取和搜索；
- 是否可以新建和更新文件；
- 是否可以删除文件；
- 是否存在远程上传限制；
- 当前仍需要用户完成的操作。

### 第五步：按权限降级

如果 Agent 只有读取权限：

- 可以检索和总结；
- 不能声称已经保存；
- 可以生成待保存的 Markdown 内容和建议路径；
- 请用户手动复制，或授权写入权限。

如果 Agent 无法访问本地目录：

- 明确说明无法直接读取或保存；
- 可以让用户上传相关文件；
- 可以生成完整 Markdown 内容供用户保存；
- 不得把聊天中的输出描述为已写入知识库。

如果 Agent 可以写入：

- 仍需遵守 `AI/AI-GUIDE.md` 的查重、预览和确认规则；
- 未经确认不得删除、覆盖、合并或大范围移动文件。

## 接入成功后的简短报告示例

```text
知识库接入检查完成。

- 路径：/Users/xxx/Work-Knowledge
- 规则读取：成功
- 本地读取：可用
- 本地搜索：可用
- 新建文件：可用，但正式写入前需要确认
- 更新已有文件：可用，但需要确认
- 删除文件：不可用/需要单独确认
- 远程上传：禁止

现在可以让我检索知识库，或整理内容并在确认后写入。
```
