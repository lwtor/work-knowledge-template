# 框架更新

框架更新是用户主动触发的独立操作，不属于初始化、查询、记录或日常维护流程。

- 没有用户明确要求时，不检查模板版本，不提示或执行升级。
- 用户明确要求更新后，先完整读取模板 `main` 分支最新的 `UPDATE.md`，以它作为本次更新的临时执行协议；本仓库旧版更新说明不能替代最新协议。
- 同时读取本仓库规则以识别附加保护；新旧保护范围取并集，无法读取最新协议时停止且不修改。
- 用户拒绝升级时，继续按当前个人仓库版本正常使用。
- 更新前展示版本差异、框架路径和受保护目录，并等待确认。
- 更新器可以在受保护目录中仅补充缺失的 README、INDEX 和 TASKS 框架入口；同名文件存在时绝不覆盖。
- Obsidian 更新只覆盖模板管理的 `work-knowledge-navigation` CSS；`.obsidian/appearance.json` 和 `.obsidian/app.json` 仅在缺失或仍为空配置时补充，已有个人外观与应用设置必须保留。
- 更新只允许操作框架文件，必须保留 `Knowledge/`、`Projects/`、`Daily/`、`Inbox/`、`Attachments/`、`Archive/`、`AI/LOCAL.md`、`AI/写入日志.md`、`AI/写入日志/`、`.kb-role` 和其他用户文件。
- Codex 完成框架复制后，先用更新后的个人仓库安装脚本重新安装 Codex 全局 `work-knowledge` Skill，再运行验证；BlueCode 对应使用 `install-bluecode-skill` 脚本，且必须提示用户重启 BlueCode 进程后新 Skill 才会加载；vBuddy 对应使用 `install-vbuddy-skill` 脚本，安装或更新后提示用户新开一个会话即可生效；其他 Agent 跳过全局 Skill 安装。
- 提交和推送分别需要再次确认。
- 更新中断后只有在再次确认且最新更新器证明全部差异均属于框架白名单时才能使用恢复开关；恢复开关不得忽略个人数据或暂存区变化。

更新器必须来自与最新 `UPDATE.md` 相同的模板版本，不得优先运行个人仓库中的旧更新器。Windows 使用模板的 `scripts/update-framework.ps1`；macOS/Linux 使用模板的 `scripts/update-framework.sh`。
