# 离线加密增量同步

当设备不能通过远程 Git 同步时，使用 `scripts/kb-transfer.py` 在两台设备之间传输加密增量包。任一设备都可以导出或导入；它不是自动双向合并工具。

## 准备

两台设备均需 Python 3、Git 和 PATH 中的 `age`。执行：

```bash
python scripts/kb-transfer.py doctor
```

## 导出

```bash
python scripts/kb-transfer.py export --out /path/to/Work-Knowledge-增量.age
```

Windows：

```powershell
py scripts\kb-transfer.py export --out E:\Work-Knowledge-增量.age
```

导出前强制运行疑似秘密扫描。传输范围仅包括 `Knowledge/`、`Projects/`、`Daily/`、`Inbox/`、`Attachments/`、`Archive/` 和月度写入日志；框架、配置和旧版日志不进入包。密码不要写在命令行。

自动化场景可使用 `--recipient-file` 和 `--identity-file`；密钥文件不得提交 Git，也不得与加密包放在一起。

## 导入

```bash
python scripts/kb-transfer.py import --package /path/to/Work-Knowledge-增量.age --vault /path/to/Work-Knowledge
```

Windows：

```powershell
py scripts\kb-transfer.py import --package E:\Work-Knowledge-增量.age --vault C:\Users\你的用户名\Work-Knowledge
```

基础版本一致时应用增量。双方已从共同基础分别修改时，导入不会覆盖任何知识文件或更新 manifest，而是在 `.kb-transfer/conflicts/<时间>/` 生成：

- `base/`：本机仍保留的共同基线文件；
- `local/`：当前本地版本；
- `incoming/`：传入版本；
- `REPORT.md`：冲突说明和文件清单。

Agent 可以比较并总结差异，但保留、覆盖或合并必须由用户确认。解决后重新导出增量包，不得直接伪造 manifest。

## 安全边界

- `.age` 是加密包，密码或私钥不得与包一起传输；
- 公司政策禁止带出资料时不得使用本流程；
- 不传输模板和 Agent 框架，框架更新仍需用户主动触发；
- 不使用网盘明文同步；
- 导入后的 Git 提交和推送需要另外授权。
